# Ask Yifan (`/ask`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jingyi types a request, attaches files, presses send, and one email with the files
reaches Yifan's inbox.

**Architecture:** A new static page `/ask` in the existing Vite app posts
`multipart/form-data` to a Cloudflare Worker at `ask.jingyifan.love`. The Worker checks the origin and the size caps and sends through the `send_email` binding. Her history lives in
`localStorage`; nothing else is stored anywhere.

**Tech Stack:** TypeScript, Vite, Vitest (node environment), Cloudflare Workers, Wrangler,
Cloudflare Email Service `send_email` binding.

**Spec:** `docs/superpowers/specs/2026-11-23-ask-design.md`

## Global Constraints

- No secret and no personal email address in the repository or the bundle. The recipient is the
  Worker secret `ASK_TO`.
- Caps: 18 MB of files per send (`18 * 1024 * 1024` bytes), 10 files, history of 50 entries.
- No key, no rate limit, no CAPTCHA (Yifan, 2026-11-23: keep it simple). The Worker's only
  checks are the allowed origin and the size caps.
- CORS: `https://jingyifan.love` and `http://localhost:5173` only.
- Every string she reads goes through `src/core/i18n.ts` in both `zh` and `en`.
- Follow the repository's conventions: feature folder with a `README.md`, pure logic in a tested
  module, DOM in the page module, a comment at the top of each file saying what it is for.
- Commit on `main`; do not push. Pushing redeploys the live site and is Yifan's call.
- No new runtime dependency in the site. The Worker may add `@cloudflare/workers-types` (dev).

## Review Focus

1. An iPhone HEIC photo or any image the browser cannot decode: it is attached untouched, never
   dropped. (Task 3)
2. Files with no text: the send goes through; the subject falls back to the first file name.
   (Tasks 1, 2)
3. A file name with Chinese, emoji, a path or a line break: Chinese and emoji survive, path
   parts and control characters are removed, and the subject cannot carry a header. (Task 2)
4. A double tap on send: one email. (Task 3)
5. Offline, or the Worker unreachable: the bubble says so, the text and files stay in the
   composer, retry works. (Tasks 1, 3)
6. Corrupt or full `localStorage`: the page opens with an empty history and still sends.
   (Task 1)

```ts
export type Env = {
  EMAIL: { send(message: unknown): Promise<unknown> };

export function handle(req: Request, env: Env): Promise<Response>;
// worker/src/index.ts

```

Response table, all JSON with the CORS headers for an allowed origin:

| Case | Status | Body |
|---|---|---|
| `OPTIONS` from an allowed origin | 204 | none |
| Origin missing or not allowed | 403 | `{ok:false,reason:'server'}` |
| Not `POST /send` | 404 | `{ok:false,reason:'server'}` |
| No text and no files | 400 | `{ok:false,reason:'empty'}` |
| More than 10 files / more than 18 MB | 413 | `too-many` / `too-big` |
| `EMAIL.send` throws | 502 | `{ok:false,reason:'server'}` |
| Sent | 200 | `{ok:true}` |

Behaviour, each a decision:

- Layout: a header card, the history as bubbles (newest at the bottom, scrolled into view), and
  a composer fixed to the bottom with a textarea that grows to six lines, a paperclip button, a
  send button, and a row of chips (name, size, remove) above it. A line under the chips shows
  the running total against 18 MB and turns red past it.
- Adding files: the paperclip (`<input type="file" multiple>`), drag and drop onto the page,
  and paste of files or images into the textarea. A pasted screenshot is named
  `截图-HHmmss.png`.
- `shrink`: for `image/jpeg`, `image/png`, `image/webp` over 1.5 MB, draw to a canvas with the
  long edge at 2400 px and export JPEG at quality 0.85; keep the result only when it is
  smaller. Any failure (HEIC, a broken image, no canvas) returns the original file.
- Enter sends, Shift+Enter breaks the line, and Enter during IME composition
  (`event.isComposing`) does nothing. On a touch device Enter always breaks the line.
- Sending: the send button is disabled and the bubble shows `ask.sending` until the promise
  settles, so a second tap cannot send twice. On success the composer clears and the entry is
  saved as `sent`. On failure the text and files stay in the composer, the entry is saved as
  `failed` with its reason, and its bubble carries a retry button that sends the composer again.
  After a reload a failed entry keeps its text and a note that the files must be added again.
- Dashboard card: title `ask.title`, blurb `ask.blurb`, no status line. The picture is a pixel
  drawing in the style of the other three (a paper plane over the town green, 2:1, PNG).
